🔴 2. Bugs détectés

🐛 Bug 1 — Textes « &apos; » visibles au lieu d'apostrophes (P1)

Sur la page d'accueil, les apostrophes s'affichent comme &apos; littéral : « Notre IA d&apos;animation transforme vos clichés » au lieu de « d'animation ».

Cause : 16 chaînes dans des arrays JavaScript (pas du JSX direct) contiennent l'entité &apos; qui n'est jamais décodée. Le JSX direct décode correctement, mais les strings JS interpolées non.

Impact : 8 occurrences visibles sur la home (FAQ, Features, HowItWorks) + 1 dans l'écran d'animation.

Fichiers : FAQ.tsx (7), Features.tsx (2), HowItWorks.tsx (1), AnimateClient.tsx (1), business/page.tsx (1), conditions-utilisation/page.tsx (2), blog-posts.tsx (2).

🐛 Bug 2 — Page /industrial inaccessible aux visiteurs (P1)

La page B2B « industrielle » redirige vers /sign-in (307) : elle n'est pas dans isPublicRoute du middleware, contrairement à /business. Une page marketing invisible pour les prospects = trafic perdu.

Fix : ajouter '/industrial' dans le middleware + rebuild.

🐛 Bug 3 — Sitemap référence des pages protégées (P2, SEO)

Le sitemap.xml contient /restore, /animate, /dashboard, /bibliotheque, /abonnement/succes — toutes inaccessibles sans connexion (307 → /sign-in). Google les signalera « Indexed though blocked ».

Fix : retirer ces URLs du sitemap (garder uniquement les pages réellement publiques et indexables).

🐛 Bug 4 — /abonnement renvoie 404 (P2)

L'URL /abonnement renvoie 404 : seules les sous-pages /abonnement/succes et /abonnement/annulation existent. La route est déclarée publique dans le middleware mais la page n'existe pas.

Fix : ajouter une redirection /abonnement → /#pricing (ou créer une vraie page tarifs).

🔵 3. Recommandations UX / best practices

  1. Accessibilité : les SVG d'icônes ont bien aria-hidden, mais vérifier les contrastes de texte text-muted sur fond sombre (contraste WCAG AA ~4.5:1).
  2. Landing pages produit : /restore et /animate sont derrière l'auth wall alors qu'elles ont un contenu marketing. Si tu veux du SEO produit, créer des variantes publiques avec CTA « Commencer » — sinon, les retirer du sitemap (Bug 3).
  3. Images demo : /demo/before.jpg et /demo/after.jpg passent par l'optimiseur Next.js — OK, mais vérifier leur poids (compresser si > 500 Ko).
  4. Robustesse textes : éviter les entités HTML (&apos;, &quot;) dans les strings JS — utiliser directement l'apostrophe droite ' (déjà le cas dans les pages légales).
  5. Performance : la home fait 206 Ko de HTML statique — excellent. Vérifier les images LCP (before/after) avec compression WebP.
  6. PWA : manifest OK (3 icônes) — vérifier qu'elles couvrent bien 192×192 et 512×512 avec purpose « any maskable ».
  7. Monitoring : garder le health check API actif ; les emails ont été désactivés comme demandé.
